## ⚠️ Decisions inside the generator

**Generated, not hand-kept** — the rule `audio-todo.mjs` already recorded: a
missing clip renders as a disabled button reading "No recording available", so
the app never complains and a hand-written list goes stale the first time the
vocabulary is edited. Rows disappear as files appear on disk.

**One clip per spelling.** `txiv` is in the vocabulary five times; that is one
recording. Homographs share too — `rau` "six" and `rau` "to put on (shoes)" are
the same syllable said the same way.

**⚠️ The owning entry is not simply the first one found.** Whichever entry owns a
spelling decides the file path, so the owner is chosen by prominence: a category
the beginner path teaches, then one a Learn lesson teaches, then anything else.
Without that rule `kuv` filed itself under `relatives` and `rau` under
`wear-verbs`, both of which the course never opens — and both already had clips
under their real category, so three rows were phantom work.

**Priority 2 is sorted by whether a Learn lesson teaches the category**, read out
of the lesson files with a regex rather than by importing `src/data/lessons.js`
— that file imports its lessons without file extensions, which Metro resolves and
Node does not. (Same trap as `learning/feature-logic/path-into-learn-guide.md` §6.)

## Adding a clip

1. Record the word alone, normally spoken. One word per mp3.
2. Save it at the path the list gives, e.g. `assets/audio/vocabulary/colors/liab.mp3`.
3. Set the entry's `audioFile` in `vocabulary.js` to the same path **without**
   the `assets/audio/` prefix — `'vocabulary/colors/liab.mp3'`.
4. ⚠️ `node scripts/generate-audio-map.js` — Metro needs a literal `require()`
   per file, so a clip missing from `src/lib/audioMap.js` **will not play** and
   nothing will say why.
5. `node scripts/recording-list.mjs --write --all` to refresh the lists.

### ⚠️ The decisions

**It is deliberately NOT everything.** The vocabulary is 1,259 spellings —
four or five hours at the microphone, most of it the reader's lookup glossary
that nobody is taught. Session 1 is what the *taught* screens read from. The
rest waits until a voice is proven rather than being chosen.

**New clips overwrite the old paths.** Chosen because it costs nothing: no
`audioFile` edits, no audio-map regeneration, nothing to switch on. ⚠️ It also
destroys the old take on contact, so **all 315 originals were copied to
`archive/2026-09-22-audio-v1/` first** — that is the only copy, and its README
has the one-line restore.

**Every row is marked `overwrite` or `new`, because they fail differently.** A
missed `new` row is a silent button. A missed `overwrite` row leaves the **old
voice in the app beside the new one** — the mixed-voice case, and the one worth
checking for. `find assets/audio -name "*.mp3" ! -newermt <session date>` lists
the stragglers; the README carries the command.

**White Hmong (Hmoob Dawb).** The vocabulary's RPA is written in it and
`dialect_preference` defaults to `'white'`, so a Green recording would not match
its own text. A Green set later needs its own paths, not these.

**`SESSION_1` in the script is the module list**, each entry carrying a `why`.
Changing the session means editing that array, not the tables.
