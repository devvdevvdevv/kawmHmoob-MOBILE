# App wouldn't boot — dependency drift (2026-07-22)

## Short version

Nothing was wrong with the app's code. Three dependencies had quietly installed
themselves at versions too new for Expo SDK 51, and the bundler refused to build.

The `^` in `package.json` means "roughly this version or newer." On a fresh
`npm install`, npm took that permission and grabbed newer releases than this
project can run. Analogy: a 2015 car, a parts list that says "any recent
alternator," and a shop that hands you the 2025 model. Better part, wrong engine.

## What was actually broken

Three separate failures, each hidden behind the one before it. Fixing the first
didn't make the app work — it just revealed the second. That's expected here,
not a sign the fix failed.

### 1. NativeWind → missing `react-native-worklets/plugin`

`nativewind` was declared `^4.0.36`, which floated up to **4.2.6**. From 4.2.0
onward it depends on `react-native-css-interop` 0.2.x, whose `babel.js`
unconditionally lists `react-native-worklets/plugin` — a **Reanimated 4**
package. This project runs Reanimated 3.10.1, so it doesn't exist.

> The error message names Reanimated, which is a red herring. Reanimated 3.10.1
> is clean — verified zero references to worklets anywhere in it. NativeWind was
> the thing doing the asking.

**Fix:** pinned `nativewind` to exactly `4.1.23` (ships css-interop 0.1.22).

### 2. Supabase → unresolvable `@opentelemetry/api`

`@supabase/supabase-js` 2.106 does an optional dynamic import for tracing:

```js
import(/* webpackIgnore: true */ OTEL_PKG).catch(() => null)
```

Node treats a failure here as fine and moves on. Metro resolves every import
statically at build time, so "optional" isn't a concept it has — a missing
module is a hard failure.

**Fix:** stubbed it in `metro.config.js` via `resolveRequest` → `{ type: 'empty' }`.
Safe specifically because Supabase already swallows the failure itself.

### 3. expo-font → version 57 in an SDK 51 project

`expo-font` is a transitive dependency of expo-router that nothing ever
declared. With no version constraint anywhere, npm installed the newest release:
**57.0.1**, against a project built around 12.x. expo-router 3.5's static web
render then died on `Font.resetServerContext is not a function` (removed
long ago).

**Fix:** declared `expo-font` explicitly at `~12.0.10`.

## Two traps worth remembering

- **`npx expo install --check` reported "Dependencies are up to date"** through
  all of this. It only inspects *declared* dependencies — expo-font wasn't one,
  so it was invisible to the check.
- **Never run `npm audit fix --force` on this project.** Its entire job is
  upgrading packages toward newest, which is precisely what caused this. It
  would undo every pin below. The ~32 audit warnings are pre-existing and
  unrelated to booting.

## Files changed

| File | Change |
|---|---|
| `package.json` | `nativewind` → exact `4.1.23`; added `expo-font: ~12.0.10` |
| `metro.config.js` | `resolveRequest` stub for `@opentelemetry/api` |

No application code was touched. Every file in `app/` and `src/` still carries
its original May 25 timestamp.

## How to verify a boot

Bundle **all three platforms**, not just one — issue #3 only ever showed up on web.

```bash
npx expo start --clear --port 8145
# then, per platform:
curl -s -o /dev/null -w "%{http_code}\n" \
  "http://localhost:8145/node_modules/expo-router/entry.bundle?platform=web&dev=true"
# repeat with platform=ios, platform=android
```

All three should return **200**. Last verified 2026-07-22:
web 5.4 MB, iOS 10.6 MB, Android 10.6 MB, plus the web route server-rendering.

## Known non-issue

A `WARN` about a require cycle inside `@supabase/auth-js`
(`webauthn.js` ↔ `webauthn.errors.js`) appears in the Metro log. That's upstream
in Supabase's own code, harmless, and not worth chasing.

## Still unverified

The above confirms the app **builds and the web route renders**. It was not
launched on a simulator or device, so runtime behavior — auth flows, audio
playback, navigation — remains unconfirmed and deserves a manual pass.
